## Requirements

### Boundary

- Keep text generation under the PHX-010 `ModelProvider` contract.
- Do **not** add embedding methods or embedding capability flags to `ModelProvider` / `ModelCapabilities` merely for PHX-014.
- Introduce a small provider-neutral embedding boundary under `phoenix/models/`, then implement its Ollama adapter.
- Memory/RAG callers must be able to depend on the neutral embedding boundary rather than Ollama response shapes.
- Do not implement PHX-015 Colibri, PHX-016 benchmark harness, Phase 3 VectorStore/RAG, document ingestion, or memory persistence.

### Candidate model

- Frozen V1 candidate: `EmbeddingGemma` through Ollama for Memory/RAG.
- The code may use a configurable model ID, but PHX-014 live smoke (if available) should prefer an already-installed `embeddinggemma` / `embeddinggemma:latest` model.
- Never treat the planning candidate as proof that the model is installed.
- Do not pull/download a model in this ticket.

### Neutral embedding contract

Define a minimal async contract such as `EmbeddingProvider` (ABC or equally strong Protocol) with:

- stable `provider_id`
- `async embed(request) -> response`

Provide frozen/validated neutral request/response models.

A request must include at least:

- operation ID (generated by default, caller-overridable)
- model ID
- ordered non-empty tuple/batch of text inputs

A response must include at least:

- operation ID
- provider ID
- model ID
- ordered immutable vectors corresponding 1:1 with request inputs
- vector dimension
- optional provider-reported timing/token metadata only where defensible

Do not expose raw provider JSON or HTTPX objects.

### Input validation

- model/provider/operation identifiers use existing PHX strict identifier semantics where practical.
- reject an empty batch.
- reject empty/whitespace-only text entries.
- preserve input order exactly.
- do not silently truncate input text.
- extra public-model fields are forbidden.

### Vector validation

- response count must equal input count.
- every vector must be non-empty.
- every vector in one response must have the same dimension.
- vector elements must be finite numeric values; reject booleans, NaN and infinity.
- expose vectors as immutable tuples (or equivalent immutable validated representation).
- preserve provider values; do not renormalize or fabricate dimensions.

### Ollama adapter

Implement a provider-specific adapter under `phoenix/models/`, for example `OllamaEmbeddingProvider`.

- provider ID: `ollama`
- default base URL: `http://127.0.0.1:11434`
- use direct `httpx.AsyncClient`; do not add the Ollama SDK or another HTTP library.
- use the modern Ollama embedding endpoint required by the installed/runtime API (normally `POST /api/embed`).
- request must map model + ordered input batch only, plus no speculative options.
- validate returned model identity where evidence is supplied, allowing only normal omitted/default `:latest` equivalence.
- validate `embeddings` before constructing the neutral response.
- finite bounded connect/read/write/pool and whole-operation timeout behavior is required.
- no HTTP request during module import or adapter construction.
- redirects must not be silently followed.
- credentials embedded in base URL must be rejected.
- keep TLS verification enabled.

### Error mapping

- unreachable/timeout/network failures -> neutral unavailable error.
- HTTP/protocol/malformed/identity/vector-shape failures -> neutral embedding/provider error.
- never fabricate an embedding response after failure.
- do not include prompts/text inputs, full raw response bodies, credentials, or private URLs in safe errors.

A small embedding-neutral error boundary is acceptable; avoid a large hierarchy.

### Resource lifecycle

- injected test client/transport is allowed for deterministic tests.
- ownership of AsyncClient must be explicit.
- provide bounded explicit async cleanup when the adapter owns the client.
- borrowed clients remain caller-owned.
- no hidden worker tasks or sockets at construction.

### Metrics

If Ollama returns defensible embedding metadata such as total duration or prompt evaluation count:

- map only provider-reported evidence.
- convert nanoseconds to milliseconds correctly.
- do not infer unavailable totals.
- do not benchmark or rank models.

### Lifecycle manager separation

- PHX-013 heavy-generation leases coordinate expensive text-generation concurrency.
- Do not automatically consume a heavy-generation lease for every embedding request in PHX-014.
- Do not modify PHX-013.
- Future benchmarks may decide whether embedding workloads need their own resource policy.

### Capability registry separation

- Do not add `supports_embeddings` to PHX-010 `ModelCapabilities` solely for this ticket.
- Do not store embedding support in PHX-012 registry.
- Embedding support is represented by using the separate embedding provider contract.

### Memory/RAG separation

Do not implement:

- chunking
- document parsing
- VectorStore
- sqlite-vec
- Qdrant
- cosine search
- retrieval
- reranking
- document/memory tables
- embedding persistence

PHX-014 only turns text batches into validated vectors.

### Events / API / frontend

- do not emit fake model/document/memory events.
- do not add embedding HTTP API endpoints.
- keep `GET /health` unchanged.
- frontend must not call Ollama directly.

### Security/privacy

- never log input texts or vectors by default.
- no credentials, shell, subprocess, filesystem, database, hardware scan, tool, permission, or frontend integration.
- provider output is untrusted until validated.
- embeddings are data only and confer no authority.
